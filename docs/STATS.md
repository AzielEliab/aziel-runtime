# /v1/stats and /v1/uses

- **Cache (STATS-CACHE-1.0):** complete KV reads are cached for up to 60s; partial reads are never cached. Each response says `cache.read_at`, `cache.age_s` and `cache.max_age_s`.
- **Floor (STATS-FLOOR-1.0):** the served `uses` is lifted to a shared floor kept in the CHAINLOCK Durable Object (no KV). Across colos the count may lag by up to 10s; within an isolate it never drops. The 10s comes from STATS-FLOOR-REUSE-1.0: an isolate reuses its last floor read for an unchanged KV count while that read is under 10s old.
- **Fail closed:** no CHAINLOCK binding, an unreachable floor, or more than 6 floor calls per isolate per minute -> HTTP 503 with `Retry-After`, and no count.
- **Breakdown:** `by_host` / `by_path` / `by_day` / `by_method` / `by_op` are the raw KV read and may lag the total (`breakdown`).
- **Speed (USES-SNAPSHOT-1.0/1.1):** the request path reads three keys (`total`, `log`, `agg|snapshot`) and never scans. `USES` is the hybrid facade (`withDurableKv`): writes go to the RUNTIME_KV Durable Object, reads try the object first and fall back to the frozen legacy KV namespace. The snapshot is built by one cron, every 30 minutes (minutes :01 and :31 of the odd-minute cron, 48 runs/day). The legacy KV maps are read once and kept as `agg|legacy` in the object; each run then reads live counters with one DO `scan` per prefix page (values included) and puts the snapshot only when the maps changed, or every 2 hours so its age stays meaningful. Responses carry `maps_source`, `maps_snapshot_at`, `maps_age_s`, `maps_complete`; a snapshot older than 3 hours is labelled stale. `uses` (the total) is always the live read.
