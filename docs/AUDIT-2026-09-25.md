## Architecture

Softwares stay cards. FragGate is the only execution door. The human UI is this runtime (`#interface-panel`, domain tabs), not a separate AZInterface product. ACT-RECEIPT-1.0 is the public mesh copy. It is not a Softwares slug and not a `tools/list` name.

```
Human workspace (aziel-runtime)
  domain tabs → dash-card tiles
  Run buttons → POST /v1/fraggate/call
  Plan / Seal pane → POST /v1/interface
        |                         |
        |                         MCP JSON-RPC method interface/orchestrate
        |                         (same body, not a tools/list name)
        v                         v
FragGate door (Lamb Lens → SweepGate → Sentinel → ChainLock-IN
  → DecisionGATE → AZPIPE → … → ForgeReceipts)
        |
        v
In-process Software op, or local-only refuse
        |
        v
ACT-RECEIPT-1.0
  isolate ledger (interface rows, previous_hash = prior isolate row)
  public chain (corpus /receipts, previous_hash = corpus tip)
```

## Receipts

ACT fields stay `hash`, `request`, `output`, `event`. Attempt ids stay inside `event`: `request_id`, `attempt_n`, `parent_receipt_id`, `correlation_id`, and `outcome`. No Software renamed those names.

`hash` is SHA-256 of canonical `{ previous_hash, request, output, event }`.

| Plane | `previous_hash` | When it is written |
| --- | --- | --- |
| Isolate ledger | Prior interface row, or 64 zero hex | Every accepted interface call, including plans |
| Public chain | Corpus tip from `GET /v1/receipts/tip` | `seal` only, and only after that tip read returns ok |

The two hashes differ. The response keeps them apart: `receipt.chain` is `isolate-memory`, `public_receipt.chain` is `act-public`. `writes_public_chain` is true only when the corpus append returned 200 or 201.

### What may land in `output`

One sentence. Status class and the FragGate code name (`FG-OK`, `FG-LAMB-REFUSE`, `IF-LOCAL-ONLY`, `no-code`). Counts of notes or tasks. The words that a plan did not launch, join, or append.

### What stays local

| Material | Where it stays |
| --- | --- |
| Passphrase, password, token, key, argv, env, credential | Refused at the interface door. Not stored, not forwarded, not hashed into a receipt. |
| AZChat handle token, passphrase salt, passphrase verifier | AZChat product store. The public room list has `passphrase_required` and `e2e: false` only. |
| VeilLock AES key, recording bytes, camera registration, argv | Local desk and CLI. This host returns no key and no argv. |
| VibeLock container bytes, PCM, accuracy numbers | Local package or the product Worker that decoded them. This runtime's learn path stores channel names and advisory scores only when analyze ran on posted features, or when the operator supplies a known hosted channel. |
| Consent values (`veil`, `call_id`, `actor`) | Unknown on this host (`null`). The field names in the VeilLock contract are not rewritten. |
| AKM notes | Isolate belief. `belief_is_not_truth` stays true. Confirm does not authorize an action. |
| Full request bodies | Not copied into `request` or `output`. |

AZChat's own `receipt_sha256` is a product hash over op metadata (`op`, `room_id`, `private`, …). It is not an ACT receipt. Do not rename it to `hash` / `request` / `output` / `event`.

A public `parent_receipt_id` is the last corpus hash this runtime appended for that `request_id`, or null. An isolate plan hash is not published as a parent.

## Findings

### Blocker — fixed on this branch

**B1. Public seal chained to the isolate ledger.** `seal` appended the isolate receipt, whose `previous_hash` is the previous interface row (or zero), not the corpus tip. That publishes a parent the public chain does not have. Fail-open skip is the honest result when the tip cannot be read. Appending a foreign parent is not fail-open.

Fix: read the corpus tip, mint a second receipt with that `previous_hash`, and append that hash. If the tip read fails, `published` stays false and `append_refuse` is `corpus-dark` or `corpus-unreachable`. No second fetch is treated as success.

### High — fixed on this branch

**H1. A failed door was outcome `completed`.** Every call, including `seal`, defaulted `outcome` to `completed` before FragGate returned. A caller could also send `outcome: "completed"` on a Lamb Lens refuse. The sentence in `output` named the code, and the hashed `event.outcome` still said the attempt completed.

Fix: if the door ran and the code is not `FG-OK`, outcome is `failed` (or `retry` when the caller asked for retry). The response `ok` is false. A local-only VeilLock seal still completes as a record, with `executed: false` and an output sentence that nothing launched.

**H2. Passphrase-shaped fields passed the secret walk.** The walk refused `password` and `token` and did not refuse `passphrase`, `passcode`, `passwd`, `pwd`, `credential`, or `bearer`. AZChat #7 stores a PBKDF2 verifier and keeps the passphrase off the list and off `receipt_sha256`. The runtime planner could still accept `payload.passphrase` and, once `room_join` is live, forward it into FragGate.

Fix: those key names are `IF-SECRET-REFUSED`. Nothing is stored and FragGate is not called. The workspace hint says this pane is not a room-join form. Private entry stays on the AZChat product.

**H3. `POST /v1/interface` was billed as a read.** The limit kind was `fraggate_read` (360/min) while `seal` can call the same live ops as `POST /v1/fraggate/call` (240/min). That is a second budget for execution.

Fix: `POST /v1/interface` is `fraggate_call`. Plans share that budget. MCP `interface/orchestrate` stays on the MCP budget (also 240/min), which matches `tools/call`.

### High — handoff, not changed here

**H4. AZChat room ops are not on this catalog.** Product draft adds `room_list`, `room_host`, `room_join` on the AZChat Worker, local engine, OpenAPI, and product MCP names `azchat_room_list`, `azchat_room_host`, `azchat_room_join`. This runtime's `LIVE_OPS.azchat` is still handle, pairwise room, bus, and `verify_receipt`. The Social card states the contract and does not execute it. `seal` of `azchat/room_join` is `op-not-live`.

Follow-up (azchat, then a reviewed runtime catalog sync): keep the passphrase on the product Worker. Do not add a passphrase field to `POST /v1/interface`. When the ops are copied into `LIVE_OPS`, the in-process engine must use the same verifier rules (no plaintext, no verifier on the list, no verifier in a receipt, refuse a passphrase when `private` is false). Raise PBKDF2-HMAC-SHA256 above 100,000 iterations (OWASP currently cites 600,000) before that sync. Product `receipt_sha256` stays a local hash. It must not be posted as an ACT receipt.

**H5. VibeLock file channels and this runtime's check list are different.** Product #14 reports `physics`, `linguistics`, `vibration`, and `related`, and refuses `container_b64` / `mp4_b64` / `media_b64` on the hosted Worker. This runtime's `analyze` emits `spectral`, `phase_continuity`, `formant`, and the rest of `VIBELOCK_CHECK_NAMES`. AZAI refuses an unknown channel and stores nothing (`IF-UNCITED`). That fail-closed behavior is correct. Alias those four product names onto spectral scores and the note would claim a measurement this isolate did not make.

Follow-up (vibelock, then runtime): keep container decode on the product. If a later learn path cites a product report, store the four names with `detector_ran: false` and `score_kind: "product-report"`, or refuse them. Do not publish an accuracy number. Do not POST file bytes to `/v1/interface`.

### Medium

**M1. Interface Seal is not tied to a prior plan.** The AZBot desk sends `seal` only for `steps[0]` after the confirm box. The interface pane sends whatever slug and op are typed, after the same box. That matches the public FragGate console on the same page: `confirm` is not authentication, and public `fraggate_call` stays open. The pane does not skip Lamb Lens. DecisionGATE still runs inside `fraggateCall`.

**M2. VeilLock host copy can drift from `suite/runtime-ui.json`.** The draft JSON says `orchestration_host.built: false`. The host overlay says `built: true` and keeps `software_contract_said_built: false`. Call names match today. A later edit to the JSON is not pulled. The desk at `127.0.0.1:8761` is not started here. Catalog commands stay a banner.

Follow-up (veillock): when the JSON changes, send the diff. Do not point the host at a second AZInterface repo.

**M3. Generic HTTP mint still uses a failed tip as zero.** `recordActReceipt` (FragGate and other POST paths) calls `fetchCorpusTip` and appends even when `tip.ok` is false, which yields `previous_hash` of 64 zeros. Interface seal no longer does that. The older minter is outside this draft's planner and was not rewritten here.

**M4. Learner memory is the first catalog sentence.** `learner_learn` with `confirm: true` observes note zero, which is a domain list, not a user secret. The store is isolate memory, cap 64. A full desk returns `IF-LEARN-FULL` and does not drop a note. `pins_read`, `mesh_read`, and `corpus_searched` stay false.

**M5. `node_mesh: true` on the overlay is the awareness call, not a join.** `mesh_awareness` does not read the roster, does not heartbeat, and does not change Live Nodes. The body says so. The boolean is easy to over-read.

**M6. Product handle tokens are in the AZChat response, not in the product receipt.** `handle_new` returns the spendable token to the caller. The receipt body is `op`, `handle_id`, `label`, `ts`. Do not copy that token into an ACT `output` if a later catalog sync seals the call from this runtime.

### Low

**L1. Domain tabs wrap on a narrow window, and search shows every domain until the box is cleared.** Stated on #168. No receipt impact.

**L2. An explicit genesis tip (HTTP 200, 64 zero hex) is a legal public `previous_hash`.** `public_tip_empty` is true. The empty tip itself is not a success receipt.

**L3. Windows 11 virtual camera in veillock#11 is user-mode `MFCreateVirtualCamera`.** This audit did not compile it or register a camera. Plans here still return no argv and do not set `have_vcam`.

**L4. stdio MCP forwards to `POST /mcp`.** `interface/orchestrate` is reached when the edge is up. It will not appear in `tools/list`.

## Security notes that held

- Local VeilLock commands (`wrap`, `engulf`, `join`, `link`, `play`, `record`, `inject`, `intercept`, `facetime`) are `IF-LOCAL-COMMAND`.
- Shell metacharacters, `..`, and non-`/dev/videoN` devices are refused. Capability flags are ignored.
- Worker text that says merge, deploy, wrangler, git push, or npm publish is `IF-WORKER-REFUSED` and stores nothing.
- VibeLock accuracy fields are `IF-UNCITED`.
- Interface paths are in `SKIP_MINT`, so the generic minter does not append a second public receipt for `POST /v1/interface`.
- No rewrite key. The isolate ledger does not drop or rewrite a full book. Cap 128 returns `IF-LEDGER-FULL`.
