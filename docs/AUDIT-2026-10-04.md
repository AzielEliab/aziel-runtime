## Executive findings

### Top risks

1. **Three writers for one not-live fact.** `currentAltInternetFact()` never accepts a caller watch, so `alt_internet_live`, `packet_path_live`, and `second_device` stay false there (`src/alt-internet-fact.js`). `d2dCarrierCite()` then forces `second_device: false` again (`src/d2d-carriers.js`). `internetBase()` copies the fact for the alt-internet flags and computes `second_device` separately from a carry’s host ids (`src/operator-surfaces.js`). A same-machine `AZMESH1` round trip stays `PACKET-CARRIED` with `second_device` false today. A future two-host carry can set the internet-base `second_device` true while `alt_internet_live` stays false.
2. **The word `live` means door-callable, not finished.** FragGate registry `live_count` is 42. That is “this slug may run an allowlisted op.” It is not an alternative internet, a public MTA, a booted kernel, or a demonstrated second device. The Whitestone Softwares card reports `status: "live"` with `fraggate_status: "none"`.
3. **Public FragGate exec is open.** `POST /v1/fraggate/call` and MCP `fraggate_call` stay on the shared `public-demo` workspace. `confirm=true` is consent bookkeeping, not authentication. `RUNTIME_TOKEN` gates session mutate only when `REQUIRE_TOKEN=1` (`src/production.js`).
4. **AZNews can mark a join live inside one isolate** after a fetched item is stored on a pin (`src/engines/4dmap/aznews.js`). That flag is process memory. It is not a Softwares card, not an MCP tool, and not `outlets_live` (that stays 0). The word `live` still collides with the catalog.
5. **Local mail can queue while public send stays refused.** `mail_send_base` sets `sent: true` and `MAIL-BASE-QUEUED` when a local SMTP sink accepts the MIME, and it forces `public_smtp_send: false` (`src/bases.js`). Catalog `smtp` / `smtp_send` / `send` / `deliver` stay `FG-STUB`.
6. **Open-world awareness is a law, not a Worker socket.** The bind cite is `0.0.0.0`. `worker_socket` is false. A local `qnm-node` listen is live-when-configured (`src/open-world-awareness.js`). That is not a loopback fence. A configured node is on all interfaces.
7. **Cap-7 control plane is marked worker-live on another Worker.** `CAP7_WORKER_FLAGS.worker_live` is true and points at `miragegrid.vibelock.workers.dev` (`src/engines/miragegrid/cap7-public.js`). `public_icann`, `public_egress_ip`, and `packet_forwarding` stay false. The LIVE label is the footgun.
8. **Cold copies are still one blast radius.** Plane B Codeberg and archive.org can PASS and stay SLOT. Zenodo is not live. Plane C USB is SLOT (`src/mcp-surface.js` instructions and `src/mesh.js` rollup text). NO-LIE refuses a single-tunnel copy set (`NO-LIE-ONE-TUNNEL`).
9. **JavaScript cannot finish a key wipe.** `src/security/keystore.js` says zeroization of `Uint8Array` copies is best-effort. Strings and WebCrypto key objects are not fully wiped.
10. **Self-test is not a third-party lab.** `2.0.0-rc1` is the certification-point freeze. `docs/2.0/` plus `scripts/verify-*.mjs` are the repo’s own watch.

## 3. Security hardening structure

### 3.1 Isolation model

Two different ideas are both in the tree. They are not the same control.

**Single-node security-awareness + phoenix reboot loop.** The standing sentence says isolation is single-node security-awareness and phoenix is a local wait and re-seal (`src/alt-internet-fact.js` `TAIL`). `neighborPhoenix()` in `src/split-wires.js` sets `local_only: true` and `phoenix: false` when a neighbor has phoenixed (`neighbors-do-not-phoenix`). Nine-law test `law4_phoenix_local_only` keeps that. Phoenix does not reach over and repair another node. It does not fence the mesh to loopback.

**Loopback is a different bind, and it is not the fence.**

- `qnsd` cite bind is `127.0.0.1` (`src/qns.js`). The Worker does not proxy it.
- Open-world awareness bind is `0.0.0.0` (`src/open-world-awareness.js`). Law status is LIVE. Worker socket is false. Local socket is `LIVE` only when a process is actually listening, otherwise `live-when-configured`.
- `forced_loopback` and `loopback_isolation` are false and are explicitly not the mesh fence (`forced_loopback_is_mesh_fence: false`).
- `mesh_fenced_to_loopback` is false on Track 2 failures (`src/fed-mesh/track2.js`).

Workspace isolation (`src/workspace.js`, `scripts/verify-workspace-isolation.mjs`) separates operator-token workspace from `public-demo`. A client-supplied `workspace_id` is not authorization. Private AZHub and AZInterface state is session-scoped or operator-token-scoped. Public FragGate state is the shared demo workspace.

### 3.2 FragGate gates

After the door admits a name:

1. **Lamb Lens** — ethics after the door. Not a second door. Order cited as Service → Clarity → Peace. Harmful harvest on AZBrowser refuses.
2. **SweepGate** (`SG-WP-0.1`, `src/sweepgate.js`) — airlock. Block keys and poison. Off-origin isolates only when inbound and untrusted. Refuse marker `sweep-isolate`.
3. **Sentinel** — hop on the strip (`src/sentinel.js`).
4. **Provenance** — input packet (`src/provenance.js`).
5. **ChainLock-IN** — stamp before exec.
6. **DecisionGATE** — five sequential gates. Freedom without clarity is chaos. A refuse still writes an ask/refuse ledger tip.
7. **AZPIPE** (`AP-WP-0.2`) — admitted payloads do not present raw inbound bytes. Illegal reorder refuses.
8. **Internal Domain Layer** — the product engine. Domains are labels, not doors (`domains_are_doors: false`).
9. **Optional ASE**, **RoseClock** (forward-only), **TemporalLock**, **ChainLock-OUT**, **ForgeReceipts**.

Rate limits and body caps live in `src/production.js` and `src/request-limits.js`. Receipt list cap is 64.

### 3.3 VeilLock local_only

Registry `statusFor`: a slug is `live` only if it has a `LIVE_OPS` entry. VeilLock does not, so status is `local_only` and every named op classifies as `FG-LOCAL-ONLY` (`src/fraggate/registry.js`). ### 3.8 What is still weak (azrt-harden)

These are incomplete for absolute stability. They are not a request to flip a flag.

1. **Split not-live writers** (§1 risk 1). `internetBase.second_device` is not `watchQualifies`. `d2dCarrierCite.second_device` is a hard false, which hides a qualified watch if one is ever passed. One function should feed every surface.

9. **Key wipe** cannot be finished in JavaScript.
10. **Cap-7 worker_live** on a different origin. This repo cites it. It does not prove the remote Worker on each test run.
11. **Self-test ≠ lab.** Adversarial scripts (`scripts/verify-adversarial.mjs`, `scripts/verify-transport-adversarial.mjs`) are in-repo.
12. **Cron plus default suite-presence** keeps software nodes warm. It does not arm radios. It does mean “presence on” is not the same as “operator opted in this minute.”

## 4. Design philosophy

### 4.1 NO-LIE / not-live-until-a-test-watches-the-door

NO-LIE (`docs/designs/NO-LIE-NO-REWRITE-1.0.md`, `src/no-lie.js`) is a law, not a product:

- Receipts that still hash.
- Copies are not all on one tunnel.
- Rules a stranger can check without the author’s voice.
- No rewrite key.
- The network does not lie to self-preserve, sustain, stay alive, adapt, or prevent death.

Not-live-until-a-test-watches is the same idea applied to flags. `src/bases.js` header: a flag is true only when that door did the work. `watchQualifies` (`src/alt-internet-fact.js`) demands `left_machine`, `arrived_other_machine`, `same_machine_id === false`, two different non-empty machine ids, and `mock !== true`. `currentAltInternetFact()` does not take a watch, so the standing fact cannot be talked into true.

Tests are the watch. `scripts/verify-surface-agreement.mjs` and `scripts/verify-operator-surfaces.mjs` pass `alt_internet_live: true` in the payload and assert the result stays false. `scripts/verify-track2-mobile.mjs` rejects `alt_internet_live: true` and `second_device: true` in `qnm-node/mobile/join.mjs`. `scripts/verify-cold-multi-shelf.mjs` locks `hash_verify_pass_is_not_live`.

A same-machine UDP exchange may return `PACKET-CARRIED` and `bytes_match`. The earned flags stay false because the packet did not arrive on a different machine id. That is the philosophy working. The harden item is to make `second_device` on `internet_base` use the same predicate, so a later real carry cannot move one flag alone.

### 4.2 Cap-7 and `.aziel` are names only

`src/engines/miragegrid/cap7-public.js` and `cap7-plane.js`:

- Factory labels: four hub mirrors (`azgrid`, `azcloak`, `azvault`, `azshift`) and three decoys (`azbooth`, `azflag`, `azstandby`).
- Those are not per-node `.aziel` slots.
- `public_icann: false`, `public_icann_registrar: false`, `public_egress_ip: false`, `packet_forwarding: false`, `hosted_vpn: false`.
- `geo-target` / `session-stick` / `egress-rotate` move a region label and a factory land among 7 sites.
- Standard internet does not reach Cap-7. AZ domains that resolve do so via hub HTTPS. That hub resolve is not Cap-7 becoming ICANN.
- `MG-NO-IP-EXIT` when a caller treats the name plane as an egress IP.
- `aznet_replaces_internet` is false (`src/d2d-carriers.js`). MirageGrid is not AZVPN.

`.aziel` names are mesh names. They are not a public registrar and not BGP (`cap7_name_only: true` on the alt-internet fact and on `internet_base`).

### 4.3 Dual hash lattices

Two lattices are in this tree. They are not the same object.

**AZNews receipt lattice** (`planReceipt` in `src/engines/4dmap/aznews.js`). Each stored document gets:

- `primary` — hash chain over the document hash and the previous primary tip.
- `secondary` — online: chain over the primary and the previous secondary tip; offline: hash of that document’s primary hash plus the username.

`lattice_live` on a document is true only when both digests match `^[a-f0-9]{64}$`. `latticesReal()` requires every chain row to list both `primary` and `secondary`. Offline duplicate secondary refuses `AZNEWS-DOUBLE` so the document is not written twice for that user. A fixture does not mark the join live. The lattice existing is not “AZNews is a live product.”

**AzielTether dual-chain** (`dual-chain` op, `src/engines/azieltether/engine.js`). Same-hash conflict between prefer-central and peer-sync. It reconciles tether items. It is not the AZNews username lattice and not a VPN.

TemporalLock / StaticClock timeslate is a third, older lattice (client-held chain, hosted does not store). It is not the AZNews pair.

`scripts/verify-4dmap.mjs` is the watch for the AZNews pair (both digests, `AZNEWS-DOUBLE`, fixture does not set join live). `scripts/verify-lattice.mjs` watches the fabric lattice (SweepGate, AZPIPE, ChainLock, LOCKSET), which is a different object.

### 4.4 Expand, do not replace

Internet, mail, and kernel bases are ops on doors that already exist (`src/bases.js` header). They do not replace AZMail and they do not add a product.

| Base | Door it extends | What stays refused |
| --- | --- | --- |
| Internet | `azos` `internet_base` | Public alt-internet, packet path, ICANN, BGP, Cap-7-as-IP |
| Mail send | `azmail` `mail_send_base` | Public `smtp_send`, public MTA, end-to-end on external SMTP |
| Kernel / userspace | `azos` `boot_path` | `booted`, `installed`, `kernel_base`, host replace |

Userspace can be a cpio-newc archive (`parseCpioNewc`) including principles text. Parsing an archive is `userspace_base`. It is not “this machine booted.” `boot_path` overwrites handoff `booted` / `kernel_base` to false before return (`src/operator-surfaces.js`).

The same expand-not-replace rule shows up elsewhere:

- SPORE does not replace cold shelves or the live front (`src/mesh.js` rollup).
- NO-LIE does not replace the machine tip (`docs/designs/NO-LIE-NO-REWRITE-1.0.md`).
- AZVPN does not replace AZNet pairing. Pairing is order and token, not a tunnel.
- Open-world awareness does not replace the ICANN internet (`replaces_internet: false`, `not_a_second_internet: true`).
- 4DMap does not replace DecisionGATE. It is an inspection frame after AZPIPE.
- Memory and mesh stay fabric. They are not new Softwares cards.

## 5. Design — Runtime ↔ AZOS cross-tether and runtime-wide dual hash lattices

Added 2026-10-05 on top of the read-only audit above. This section is a design, not a claim that the work is live. It names what the code has to do before `lattice_live` or `azos_updated` can be true. Nothing in this section is live at `b7a91aa` or at `9190757` (the GLAMA sync tip).

### 5.1 Decision: the AZOS `lattice` refusal stays

The runtime refuses `azos` `exec`, `shell`, and `lattice` on the public door (`STUB_OPS.azos` in `src/fraggate/registry.js`). That refusal is REMAIN-OFF item 8 (AZ-OS shell / exec on the public door). It stays in place.

The tether does not use that op. It does not run code inside AZ-OS. It does not open an AZ-OS shell session. It does not call AZ-OS `POST /v1/exec`. It does not reuse the AZ-OS `POST /v1/lattice` TemporalLock bind route on the tracker, which is a different object.

The rule is one way: the runtime **sends** a signed record, and AZ-OS **checks and stores** it over its own tracker API. AZ-OS can refuse. The runtime never reaches into AZ-OS.

### 5.2 Runtime-wide dual hash lattices

Today only AZNews receipts carry two chains (`planReceipt` in `src/engines/4dmap/aznews.js`). The design moves the hash rules into one shared module and applies them to every stored document and receipt on the runtime, starting with ChainLock stamps and session receipts.

Every document gets these fields:

| Field | Rule |
| --- | --- |
| `document_hash` | SHA-256 of the canonical document content. For a ChainLock stamp this is chain, kind, subject, and fact. Ids and timestamps are not part of it, so the same document hashes the same way twice. |
| `primary` | `H({document: document_hash, prev: primary_prev})`. A hash chain over every document in order. |
| `secondary` (online) | `H({offline: false, prev: secondary_prev, primary})`. A second chain that moves with the first. |
| `secondary` (offline) | `H({primary: document_hash, username})`. The document's own primary hash plus the username. |

When the user is offline, the secondary hash does not depend on the order of the chain. The same document from the same user always gives the same secondary hash. A second write of that document is refused (`LATTICE-DOUBLE`), so a document can never be doubled while the user is offline. The username is a short handle. A legal name is not stored.

Verification walks both chains. A broken `primary_prev`, a broken `secondary_prev`, a recomputed digest that does not match, or two offline rows with the same secondary hash all fail closed. Old rows written before the lattice existed are labeled `legacy` and do not count toward `lattice_live`.

`lattice_live` may be true for a chain only when every non-legacy row stores both digests and the verifier passes. Tests have to fail if the flag is true while a row is missing one chain. A row that only exists in isolate memory may say `lattice_live` for that row. It does not make the catalog or a Softwares card live.

### 5.3 Cross-tether protocol

1. **Runtime side.** The runtime builds a tether packet for one chain: the chain name, the new dual-lattice rows since the tip AZ-OS last acknowledged, both tips, the runtime git SHA, and a timestamp. It signs the canonical packet with an Ed25519 key held only as a Worker secret (`TETHER_SIGNING_SEED`). The public key is published on the runtime so anyone can check it. If the secret is absent, the push refuses `TETHER-KEY-ABSENT` and `azos_updated` stays false.
2. **Transport.** The runtime posts the packet to the AZ-OS tracker with the existing `AZOS` service binding (`POST /v1/tether/tip`). That is an HTTP call to the tracker's own API. It is not FragGate `azos` `lattice`, and it is not exec.
3. **AZ-OS side.** The tracker checks the Ed25519 signature against the runtime public key pinned in its own config (`RUNTIME_TETHER_PUBKEY`). It recomputes every row's `primary` and `secondary`, checks that the first row links to the tip it already stored (or to genesis on first contact), and refuses an offline doubled secondary. Only then does it write the new tips to its own KV. Any failure is a refusal, and nothing is stored.
4. **Read back.** AZ-OS `GET /v1/tether` returns the stored tips per chain, the pinned key, and `verified: true` only for tips it checked. The runtime reads that receipt back. `azos_updated` is true on the runtime only when AZ-OS returned a stored, verified acknowledgment for that exact tip.

### 5.4 What stays off

- AZ-OS `exec`, `shell`, and `lattice` on the runtime door stay refused (REMAIN-OFF item 8).
- The tether is not mesh membership. It does not set `mesh_node`, `second_device`, `alt_internet_live`, or `packet_path_live`.
- The tether does not boot AZ-OS, install it, or mark it an operating system.
- A signed tip is an integrity record. It is not courtroom proof and not a public ledger.
- No new Softwares card (stays 42). No new MCP tool (stays 36).

### 5.5 Tests the build has to add

- Runtime: both chains on every ChainLock stamp and session receipt, an offline double refused, a tampered secondary fails verify, `lattice_live` false when one chain is missing, and a signed packet that verifies with the published key and fails with any other key.
- AZ-OS: a valid packet stores and reads back as verified, a bad signature is refused and nothing is written, a broken link is refused, an offline double is refused, and `/v1/exec` and the runtime `azos` `lattice` refusal are unchanged.
