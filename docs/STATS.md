# /v1/stats and /v1/uses

- **Cache (STATS-CACHE-1.0):** complete KV reads are cached for up to 60s; partial reads are never cached. Each response says `cache.read_at`, `cache.age_s` and `cache.max_age_s`.
- **Floor (STATS-FLOOR-1.0):** the served `uses` is lifted to a shared floor kept in the CHAINLOCK Durable Object (no KV). Across colos the count may lag by up to 10s; within an isolate it never drops. The 10s comes from STATS-FLOOR-REUSE-1.0: an isolate reuses its last floor read for an unchanged KV count while that read is under 10s old.
- **Fail closed:** no CHAINLOCK binding, an unreachable floor, or more than 6 floor calls per isolate per minute -> HTTP 503 with `Retry-After`, and no count.
- **Breakdown:** `by_host` / `by_path` / `by_day` / `by_method` / `by_op` are the raw KV read and may lag the total (`breakdown`).
- **Speed (USES-SNAPSHOT-1.0/1.1):** the request path does not scan. It reads the log, the snapshot, and the total. `USES` is the hybrid facade (`withDurableKv`): writes go to the RUNTIME_KV Durable Object, reads try the object first and fall back to the frozen legacy KV namespace. The snapshot is built off the request path by the odd-minute tether cron. A snapshot that has never been built is published at minutes :01 and :31 (48 runs/day). A snapshot older than 3 hours, or a resumable build still in progress, is rebuilt on the next odd-minute tick (about every 2 minutes). GET /v1/stats and /v1/uses do not start that scan. A stale snapshot stays the last maps, with maps_refresh "due", and is not zero-filled. The legacy KV maps are read once and kept as `agg|legacy` in the object; each run then reads live counters with one DO `scan` per prefix page (values included) and puts the snapshot only when the maps changed, or every 2 hours so its age stays meaningful. Responses carry `maps_source`, `maps_snapshot_at`, `maps_age_s`, `maps_complete`; a snapshot older than 3 hours is labelled stale. `uses` (the total), when RUNTIME_KV is bound, is the frozen legacy USES `total` plus the Durable Object `total` (`uses_legacy`, `uses_durable`, `uses_total_source`). That sum is computed on read and is not written back. On a plain USES namespace, `uses` is that namespace's `total`.
